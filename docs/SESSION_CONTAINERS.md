# Isolated Dev Sessions With Accurate Edges

Running many agents/sessions against one working tree causes churn; running them
fully isolated causes a different cost — the isolated piece builds against a
**faked edge**, "thinks" it is correct, and breaks at real integration. The fix
is not more isolation, it is **edge fidelity as a boot precondition**: a session
is not handed over until the interfaces it builds against and the data it serves
are provably current against the real producer, or the boot fails closed.

## The model

Each session picks a **profile** that materializes only the edges it consumes —
the same philosophy as the MCP bridge exposing a declared *subset* of the inspect
API rather than a full mirror. Absence of an edge is not a gap.

| Profile | Edges it boots | Cargo rebuild? | Live Postgres? |
|---|---|---|---|
| `frontend` | `iface:api-types`, `data:golden_capture`, real inspect + SPA | no | no (seed only) |
| `backend` | `iface:sqlx`, build | yes | **no** — builds DB-less against `.sqlx` |
| `db` | `iface:sqlx`, `data:golden_capture`, real proxy + inspect | yes | yes (per-session clone) |

## Two kinds of edge — both derived, never hand-authored

1. **Interfaces** (`iface:*`) — derived artifacts (the `.sqlx` query cache; the
   generated frontend API types) verified in **two layers**:
   - **Boot (fast, here):** the committed artifact is hash-pinned in
     `scripts/.edge/<name>.hash`. If it changed since the last `reconcile`
     (a hand-edit, or regenerated-without-reconcile), boot fails. No build, no
     DB — a sub-second gate that does not false-flag on unrelated source edits.
   - **CI (authoritative):** the artifact is regenerated from the Rust producer
     and diffed — `scripts/check-generated-types.sh` for the TS types,
     `scripts/sqlx-prepare` for `.sqlx`. This is the "artifact matches the
     producer" guarantee; it needs a build, so it is not a boot check.

   The frontend API types are generated by **`ts-rs`** from the inspect-API
   response DTOs (feature-gated, normal builds never compile `ts-rs`):

   ```
   cargo test -p mike --features ts-export export_bindings
   scripts/session-up.sh reconcile        # re-stamp the boot hash-pin
   ```

   Generated files land in `frontend/src/lib/api/generated/` (do not hand-edit).
   This closes the previously-ungated frontend↔inspect-API seam: a DTO change
   without a regenerate fails CI, and a regenerate without a reconcile fails boot.

2. **Data** (`data:<template>@<hours>`) — a golden template DB **cloned per
   session** (`CREATE DATABASE … TEMPLATE`, instant and identical every time),
   refused if the template's `meta.golden_provenance.captured_at` is older than
   the freshness budget. True data is a real captured snapshot restored with
   referential integrity — not synthesized fixtures that omit the edge cases that
   break integration.

## Commands

```bash
scripts/session-up.sh profiles                 # list profiles + their edges
scripts/session-up.sh reconcile                # re-stamp iface baselines after an
                                               # intentional regenerate
scripts/session-up.sh backend                  # boot a profile (fail-closed preflight)
scripts/session-up.sh frontend --max-data-age 6
scripts/session-up.sh db --no-clone            # skip the data clone (iface-only check)

# Build/refresh the golden template from REAL captured data + stamp provenance:
scripts/session-data-refresh.sh --template golden_capture \
    --source-url postgres://postgres:postgres@127.0.0.1:6666/mike
```

`MIKE_TEST_ADMIN_URL` (must point at `.../postgres`) is the admin connection
used to clone templates, matching the `TestDb` convention. The boot is
fail-closed at every step, mirroring the `start-proxy.sh` DB probe and the
`preflight-toolchain.sh` self-heal.

## When the producer changes

A producer change **without** a matching `reconcile` is exactly the drift this
catches — boot fails until you regenerate the artifact (`scripts/sqlx-prepare`, the
TS type generator) and re-stamp with `scripts/session-up.sh reconcile`. Baselines
are per checkout: the first boot in a checkout stamps them.

## Relationship to the existing stack

`session-up.sh` does not replace `start-proxy.sh`; it is the **gate that runs
before it**. It can be the entrypoint of a per-session container or the first
step in a worktree session. The interface checks need no database (they hash
source); only the `data:*` clone needs Postgres — so `backend` and `frontend`
logic work proceeds DB-less.
