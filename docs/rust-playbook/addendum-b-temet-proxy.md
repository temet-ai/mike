# Addendum B — What to do on temet-proxy

> Every chapter before this one is portable: the lessons transfer to any Rust service. **This part does
> not.** It is the project-specific operating layer — the concrete backlog, the agent/skill wiring, and
> the `CLAUDE.md` edits that turn the playbook's lessons into actions *here*. Read it against current
> ship-state, not the playbook's idealized one: several of the obvious recommendations are already
> shipped, and saying so is the point. The frame throughout is **shipped here as X → the portable or
> still-missing piece is Y**; anything that can't be grounded that way was cut.

## B.2 — Skills & agent changes

Grounded in the existing five agents (`db-dev`, `frontend-developer`, `rust-developer`, `ui-designer`, `watchdog`), the shipped hook/rule stack, and the [CS-5](./case-studies.md#cs-agent-forensics) forensics. Bias: **portabilize what's shipped, add only what's missing** — don't re-propose the routing table, verification gate, or executable self-check (all already live).

**New agents worth adding**
- **`technical-writer` (docs / playbook authoring)** — *what:* a read-mostly agent that owns `docs/` prose, the ROADMAP/ARCHITECTURE living docs, and playbook-style synthesis; *why:* this addendum and the playbook itself were authored by a general agent with no doc-discipline brief, and Appendix A.4 names the rustdoc/doctest gap with no owner; *shape:* `description: docs + ARCHITECTURE/ROADMAP upkeep + rustdoc; may edit *.md and /// doc-comments, never production *.rs/*.svelte logic`.
- **`scope-guard` (structural dispatch gate)** — *what:* a `PreToolUse`-on-dispatch hook (not a persona) that rejects a sub-agent brief exceeding **2× the operator instruction length** and strips auto-attached `<command-name>` skill bodies the operator didn't name; *why:* prose routing/brief-cap rules failed under pressure ([CS-5](./case-studies.md#cs-agent-forensics): `MUST`/`ALWAYS` produced more confident *overriding*; brief-amplification confession in forensics); the cap belongs in a deterministic gate, mirroring how F1 replaced prose weasel-rules; *shape:* one bash hook, `len(brief) > 2*len(instruction) → {"decision":"block"}`.

**Changes to existing agent briefs**
- All five agents already point at `inspection-fidelity.md`; **add the executable self-check command to each agent's completion checklist by reference** (not by inlining it) so it fires per-agent, not only at the orchestrator. One line: *"before claiming done, run the fidelity grep from `inspection-fidelity.md §self-check` and paste output."*

**New / changed skills**
- **Portabilize the inspection-fidelity self-check as a repo-agnostic skill** — *what:* the grep + paste-output discipline already lives as an executable block in the rule; lift it into a `Skill` so it travels to other repos and can be invoked, not just remembered; *why:* it is currently a single-repo rule body; the playbook's no-truncation lesson ([ch. 10](./parts/10-T09-observability-fidelity.md)) is fully portable. **Do not "invent" it — it ships here; the missing piece is reuse.**
- **Wire the fidelity grep into `pre-commit-gate.sh`** — *what:* the gate runs G1/G3/G4 (DB/migration/sqlx) but not the truncation grep; add it as G5; *why:* makes the fidelity check unskippable at commit time, the same deterministic-gate move as F1. *(Pairs with B.1 #3 — the full clippy/nextest suite still needs CI; the gate is commit-time, CI is merge-time.)*
- **Deterministic-gate discipline is already a skill in practice** (F1 Stop/SubagentStop) — the portable lesson is *encode adherence as a gate, not prose*; the still-open piece is the B.1 #7 hardening, not a new skill.

## B.3 — CLAUDE.md changes

The playbook's own lesson governs this section: **load-bearing rules go early and short; prose `MUST`/`ALWAYS` is a weak lever** ([ch. 17 — Lean main turn](./parts/17-T13b-lean-main-turn.md), [CS-5](./case-studies.md#cs-agent-forensics); the "lost in the middle" effect). The shipped `CLAUDE.md` already front-loads the routing table, the verification gate, and the brevity-as-exhaustion clause — **do not re-add those.** Net line count should go **down or flat**: prefer moving enforcement into the hooks/skills above over growing the file.

**Proposed edits (net-negative):**

1. **Move the MCP-bridge parity paragraph out of prime real estate.** Lines 14–22 spend ~9 lines of the file's most-read region on reference detail (manifest/parity-test mechanics). That is exactly the "load-bearing real estate spent on reference" anti-pattern. *Before:* the full `**MCP bridge** (stdio) — … parity test pass.` block in Project Overview. *After:* one sentence — `**MCP bridge** (stdio) — `proxy-mcp` exposes the inspect API as MCP tools; coverage parity is enforced (see `ARCHITECTURE.md:143-152`).` — and relocate the mechanics to `ARCHITECTURE.md` (adding an `## MCP parity` heading there if a named anchor is wanted; none exists today — the parity prose is unheaded at `:143/:152/:675`). **Saves ~7 lines from the highest-attention region.**

2. **Hoist nothing new as prose; hoist enforcement into gates.** The verification-before-completion block (lines 46–56) is correct but prose-dependent. Don't expand it — add the B.2 `scope-guard` dispatch hook and the G5 fidelity gate so the enforcement is structural, then the prose can shrink to a one-line pointer at the hooks rather than re-stating each rule. (Tracked as a follow-up once the gates land; do not pre-shrink the prose before its structural replacement exists.)

3. **Fix the stale tool count — in the skill, not `CLAUDE.md`.** `CLAUDE.md:16` ("**49 tools**") is **correct**: it matches the test-enforced source of truth (`crates/proxy-mcp/src/tools.rs` — `all_tools()` has 49 entries; `assert_eq!(tools.len(), 49)`) and `ARCHITECTURE.md:152/675`. The stale source is the **skill** `.claude/skills/mcp-temet-proxy/SKILL.md` (says "29 tools"; its own text even admits the catalogue grew past it). Correct the SKILL to 49 (or drop the count there and link `crates/proxy-mcp/src/tools.rs`). **Net change to `CLAUDE.md`: zero** — leave the 49 as-is.

**Explicitly NOT proposed** (already shipped this cycle, per `07-fix-plan.md` / `08-status.md`): the Routing-to-Agents table, the "verification theater" framing, the late-session-brevity clause, the project-local `scope-and-agents.md` override, and the executable self-check in `inspection-fidelity.md`. Re-proposing them would be the inverse of the lesson.
