Problem — Current flat layout (before)
The current .step__head is a single flex row: caret → RESULT → tool-name → summary → toks. For long MCP names (mcp__claude-in-chrome__computer), the tool name consumes ~205px at flex-shrink: 0 before the summary column starts. The summary then holds collapseWhitespace(fullText) — all 1200 chars on one line wrapping across ~10 lines. Findings 2, 4, and 5 from the #30041 review all trace to this layout.

Implementation Spec
New DOM structure (replaces .step / .step__head): 
.steps-v2
  .step-v2 [.step-v2--result | --tool | --system | --error] [.step-v2--open] [.step-v2--no-more]
    <button> .step-v2__kind-row            ← Row 1: always visible, click target
      .step-v2__caret                       ← ChevronDown (lucide), rotated -90deg when closed
      .step-v2__kind                        ← "RESULT" / "TOOL" / "SYSTEM" (uppercase via CSS)
      [.step-v2__error-badge]               ← "error" badge if is_error
      .step-v2__toks                        ← ~305 tokens (margin-left: auto → right-justified)
    </button>
    <span> .step-v2__tool-name             ← Row 2: block.tool_name, full-width, own line
    <span> .step-v2__firstline             ← Row 3: firstLine(block.text), pre-wrap
    [<span> .step-v2__more-hint]           ← Row 4: "↳ N more lines" (hidden when open / no-more)
    [<pre>  .step-v2__body]               ← Row 5+: remainingLines(block.text), hidden → block
firstLine / remainingLines split (TypeScript, in RequestBand.svelte): 
function splitFirstLine(text: string): { first: string; rest: string; hasMore: boolean } {
  const nl = text.indexOf('\n');
  if (nl === -1) return { first: text, rest: '', hasMore: false };
  // Trim leading blank lines from rest so the body doesn't start with whitespace
  const rest = text.slice(nl + 1).replace(/^\n+/, '');
  return { first: text.slice(0, nl), rest, hasMore: rest.length > 0 };
}
Inspection-fidelity contract: first is the full first line — never sliced. rest is every remaining byte — never sliced. The hasMore flag gates the caret and more-hint rendering. rest.length === 0 → .step-v2--no-more.
Token deduplication (.msg__role .toks):
In Svelte: compute singleStepNoProse = steps.length === 1 && prose === ''. When true, add msg--single-step to the .msg element. CSS rule: .msg--single-step .msg__role .toks { display: none }.
When false (multiple steps or prose present), the .toks shows the message total — meaningful because it differs from any individual step count.
280px max-height removal:
Delete max-height: 280px from .step__body (RequestBand.svelte:1292). Keep overflow: auto. The body is bounded by the column scroll container; content is never capped mid-stream. For the new .step-v2__body, do NOT add a max-height.
