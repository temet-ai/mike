Design annotations

Visual differentiation: file-modifying tools
Tools that change files on disk — Edit, Write, MultiEdit, NotebookEdit, NotebookEditCell — get:
  • Amber left border (2px, always-on) — uses the same amber token as the "where am I" cue but always on (not hover-only), because the amber here signals "this row made a change," not "you are reading this."
  • Amber tool name color (var(--amber)) — reinforces the left border without adding a background fill (avoids the flat-block mistake).
All other tools: neutral --border-subtle left border, --text-strong tool name.
Bash accent (blue)
Bash gets var(--blue) tool name. Rationale: blue = "execution / info" in this palette (same as request info and ring/focus tokens). This gives the operator an instant signal for "shell command ran here."
Task accent (teal)
Task (subagent dispatch) gets var(--teal). Teal = tertiary accent — distinct from amber (file change) and blue (shell exec), so Task stands apart as "delegation" rather than direct I/O.
No truncation: input JSONB
The full input JSON blob renders in an overflow-y:auto scroll container with max-height: 320px. This is a scroll window, not a data truncation. All bytes are in the DOM once the row is expanded. Never use JSON.stringify(input).slice(0, N) or class="line-clamp-*" here. See docs/frontend/style/common-mistakes.md § Inspection Fidelity.
file_path display: no truncation
Long paths wrap via word-break: break-all; overflow-wrap: anywhere. They do not ellipsis. Operators need to read the full path to determine which file was affected — capping to 40 chars would require a hover to confirm.
MultiEdit: null file_path handling
MultiEdit has an edits: [{file_path, old_string, new_string}] input shape and no top-level file_path. When file_path is null, the implementation should: (a) render no path span, (b) show "N files" from input?.edits?.length as an arg-preview. The full edits array is in the expandable input section. Never render partial path lists.
Arg preview for Bash / Task
The inline preview for Bash shows input.command (the full command string). For Task it shows input.description (the subagent brief label). This is not a truncated slice — it is a well-defined field extracted from the input object. The full input remains in the expandable section. If the command/description is long, it wraps — it does not ellipsis.
ord field tooltip
ord is the 0-indexed position of this tool call in the parent request's tool_calls array. Displayed as #N (1-indexed for human display: ord + 1). Tooltip on hover: "Nth tool call in request #R". Helps the operator correlate the row with the raw SSE stream order.
tool_id field tooltip
tool_id is the Anthropic-generated call ID (toolu_xxx). Displayed at caption size, muted. Tooltip: "Anthropic tool call ID — matches the toolu_xxx ID in the raw SSE stream". Truncated in display to first 12 chars + … because the full ID is noise at this scale — the full value is shown in the tooltip and in the expanded input JSON. (This is UI chrome truncation of an ID, not content truncation — the full ID is always reachable.)
Empty state
When GET /api/sessions/{id}/tool_uses returns an empty array: show the wrench icon at 40% opacity, the text "No tool uses recorded", sub-text "Tool calls appear here once the session makes its first tool use." Do not hide the panel — the header + empty state still communicate that the data category was checked and came up empty.
